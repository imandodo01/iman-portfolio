## 3. Content rules

- Keep personal products, professional experience, and employer contributions clearly distinct.
- Do not imply ownership of an employer's whole system when the contribution was narrower.
- Do not publish proprietary source code, internal URLs, customer data, confidential architecture, or unapproved screenshots.
- Use only verified release status, features, technology, dates, and measurable outcomes.
- Treat project backlog items as ideas, not delivered capabilities.
- Keep wording editable until the user explicitly approves final copy.
- Prefer specific evidence and clear context over inflated claims or generic marketing language.

## 4. Revisit triggers

Review this inventory when:
- Qraft receives a meaningful new release.
- Another personal project reaches a presentable milestone.
- A professional project has approved public scope and evidence.
- The user supplies updated experience details or wants to change the portfolio narrative.
- The visual design is finalized and copy length needs to be adjusted to the actual layout.
